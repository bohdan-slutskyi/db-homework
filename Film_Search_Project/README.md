# Film Search Project

Веб-приложение на Python для поиска фильмов в базе данных **MySQL Sakila**.
Проект показывает совместное использование реляционной базы данных MySQL для
каталога фильмов и документной базы MongoDB для истории поисковых запросов и
статистики.

---

## Описание проекта

Приложение позволяет искать фильмы по части названия, жанру и диапазону лет.
Результаты отображаются постранично. Каждый реальный поисковый запрос
сохраняется в MongoDB, а на главной странице доступны последние уникальные и
популярные запросы.

---

## Функциональные возможности

- Поиск по части названия: функция `normalize_keyword()` очищает строку
  методами `strip()` и `lower()`, а MySQL выполняет параметризованный поиск
  `LIKE %s` по всему названию.
- Поиск по жанру, конкретному году или диапазону лет. Несколько условий
  собираются в списки `conditions` и `parameters`, после чего объединяются в
  один SQL-запрос.
- Дополнительные фильтры: актёр, возрастной рейтинг, стоимость аренды и
  длительность фильма.
- Пагинация: целочисленный расчёт `offset` и не более десяти фильмов на
  странице.
- Сортировка каталога по году выпуска.
- Отдельная страница с подробностями фильма.
- Сохранение каждого реального поиска как отдельного словаря-документа
  MongoDB методом `insert_one()`.
- Статистика через MongoDB Aggregation Pipeline: пять последних уникальных и
  пять популярных запросов.
- Локальные файлы логов: поисковые события и ошибки.
- Безопасная обработка ошибок MySQL и MongoDB с помощью обработчиков FastAPI и
  общего Python-декоратора.

## Используемые данные

### MySQL Sakila

MySQL хранит данные каталога:

- `film` — название, год выпуска, описание, рейтинг, стоимость аренды и
  длительность;
- `category` — жанры;
- `film_category` — связь фильмов и жанров;
- `actor` и `film_actor` — актёры и их связь с фильмами.

Результат `cursor.fetchall()` первоначально представляет собой список
кортежей. Функция `build_catalog_film_rows()` с помощью спискового включения
преобразует его в `list[CatalogFilmRow]`. Класс `CatalogFilmRow` хранит ID,
название, описание, год выпуска, рейтинг, стоимость аренды, длительность и жанр
фильма.

Вспомогательные SQL-запросы возвращают:

- жанры — `list[str]`;
- актёров — `list[tuple[int, str, str]]`;
- минимальный и максимальный годы выпуска —
  `tuple[int | None, int | None]`.

### MongoDB

Объекты `MongoClient`, `database` и `Collection` выбирают базу `film_search` и
именованную коллекцию `final_project_060326-ptm_Bohdan_Slutskyi`. Каждый
выполненный поиск преобразуется в словарь со следующими ключами:

- `timestamp` — время выполнения поиска;
- `search_type` — сценарий поиска: по названию или по фильтрам;
- `params` — параметры поиска;
- `results_count` — полное число найденных фильмов.

Последние запросы строятся как уникальные сочетания `search_type` и `params`.
Популярные запросы строятся MongoDB Aggregation Pipeline и показывают число
повторений. Все реальные поиски сохраняются отдельно; уникальность применяется
только при формировании статистики последних запросов.

## Реализация основных требований

### Поиск по части названия

Функция нормализации возвращает строку без пробелов по краям и приводит её к
нижнему регистру. Благодаря этому `Dino`, `DINO` и `dino` используются как одно
значение для поиска и статистики:

```python
def normalize_keyword(keyword: str) -> str:
    return keyword.strip().lower()
```

Символы `%` с обеих сторон позволяют искать совпадение в любой части названия.
Значение передаётся в SQL отдельно от текста запроса:

```python
search_value = f"%{keyword}%"
cursor.execute(query, (search_value, offset))
```

```sql
WHERE f.title LIKE %s
```

### Поиск по нескольким фильтрам

SQL строится из отдельных частей. Условия и пользовательские значения хранятся
в разных списках:

```python
conditions: list[str] = []
parameters: list[str] = []

if conditions:
    query_parts.append("WHERE " + " AND ".join(conditions))

cursor.execute(query, tuple(parameters))
```

Список `conditions` содержит части `WHERE`, а список `parameters` — значения
жанра, годов, рейтинга, цены, длительности и актёра. Метод `join()` объединяет
выбранные условия через `AND`, а `tuple(parameters)` передаёт значения драйверу
MySQL отдельно от SQL.

Диапазон лет формируется параметризованным условием:

```python
range_condition = "f.release_year BETWEEN %s AND %s"
range_parameters.extend([year_from, year_to])
```

### Пагинация по десять фильмов

Номер страницы преобразуется в смещение:

```python
offset = (page - 1) * 10
```

Страница 1 получает `offset = 0`, страница 2 — `10`, страница 3 — `20`.
Ограничение применяется непосредственно в SQL:

```sql
LIMIT 10 OFFSET %s
```

Полное количество совпадений отдельно вычисляется через `COUNT(*)`, поэтому
интерфейс знает общее число страниц, а не только размер текущей выдачи.

### Сохранение поискового запроса в MongoDB

Функция `log_search()` создаёт обычный словарь Python:

```python
search_document = {
    "timestamp": datetime.now(),
    "search_type": normalized_search_type,
    "params": params,
    "results_count": results_count,
}
```

Метод PyMongo сохраняет этот словарь как документ MongoDB:

```python
collection.insert_one(search_document)
```

Переход по страницам выдачи не вызывает `log_search()` повторно, поэтому один
пользовательский поиск создаёт один документ.

### Пять последних уникальных запросов

MongoDB получает `pipeline` — список словарей с этапами агрегации:

```python
{"$sort": {"timestamp": -1}},
{
    "$group": {
        "_id": {
            "search_type": "$search_type",
            "params": "$params",
        },
        "timestamp": {"$first": "$timestamp"},
        "results_count": {"$first": "$results_count"},
    }
},
{"$sort": {"timestamp": -1}},
{"$limit": safe_limit},
```

Уникальность создаёт `$group` по составному ключу `search_type + params`.
Первая сортировка располагает документы от новых к старым, а `$first` оставляет
самый новый экземпляр каждой группы. Вторая сортировка упорядочивает уже
уникальные запросы, после чего `$limit` оставляет пять записей.

### Пять популярных запросов

Популярность также рассчитывается в MongoDB:

```python
{
    "$group": {
        "_id": {
            "search_type": "$search_type",
            "params": "$params",
        },
        "count": {"$sum": 1},
        "timestamp": {"$first": "$timestamp"},
        "results_count": {"$first": "$results_count"},
    }
},
{"$sort": {"count": -1, "timestamp": -1}},
```

Оператор `$sum: 1` подсчитывает число документов в каждой группе. Сортировка
сначала располагает запросы по убыванию частоты, а при равной частоте — от
новых к старым.

## Технические особенности

- Повторно используемые сценарии вынесены в функции `run_keyword_search()` и
  `run_filtered_search()`. Они возвращают кортежи с нормализованными
  параметрами, списком фильмов и полным количеством результатов.
- SQL-условия хранятся в `list[str]`, а параметры передаются в
  `cursor.execute()` отдельным кортежем. Пользовательский ввод не подставляется
  напрямую в текст SQL.
- Результаты каталога представлены объектами класса `CatalogFilmRow`, а
  документы и контекст HTML-страницы — словарями Python.
- MongoDB Aggregation Pipeline представлен списком словарей и выполняется
  методом `collection.aggregate(pipeline)`.
- Фабрика декораторов `log_mongo_action()` содержит вложенные функции
  `decorator()` и `wrapper()`. Блок `except PyMongoError` записывает безопасный
  тип ошибки и возвращает запасное значение, поэтому сбой MongoDB не мешает
  поиску фильмов в MySQL.
- Обработчики с декораторами `@app.exception_handler(...)` возвращают при
  ошибке MySQL безопасный HTML- или JSON-ответ без параметров подключения.
- Блоки `finally` закрывают курсор и соединение MySQL после каждого запроса.
- Функции содержат аннотации типов `list[...]`, `tuple[...]`, `dict[...]` и
  аннотации возвращаемых значений.
- Поисковые события и ошибки записываются разными объектами `Logger` в файлы
  `search.log` и `error.log`.
- Uvicorn запускает приложение как `app.main:app`, поэтому отдельный блок
  `if __name__ == "__main__":` не требуется.

## Настройка и запуск

### Предварительные условия

- Podman с Compose. Для Ubuntu: [официальная инструкция по установке Podman](https://podman.io/docs/installation).
- Или Docker Engine с Docker Compose Plugin. Для Ubuntu: [официальная инструкция по установке Docker](https://docs.docker.com/engine/install/ubuntu/).
- Доступ к MySQL-серверу с базой данных Sakila.

### Локальные параметры MySQL

Рядом с `compose.yml` создаётся локальный файл `.env` на основе
`.env.example`:

```dotenv
MYSQL_HOST=your_mysql_host
MYSQL_PORT=3306
MYSQL_USER=your_mysql_user
MYSQL_PASSWORD=your_mysql_password
MYSQL_DATABASE=sakila
```

MongoDB запускается Compose как отдельный внутренний сервис, поэтому параметры
подключения к нему для обычного запуска добавлять в `.env` не требуется.

### Запуск

```bash
podman compose -f compose.yml up --build -d app
```

При использовании Docker Compose применяется аналогичная команда:

```bash
docker compose -f compose.yml up --build -d app
```

После запуска сайт доступен по адресу:

```text
http://localhost:5001/
```
